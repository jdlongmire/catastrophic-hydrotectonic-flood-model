# 2.5-verification/

How a claim in this programme is verified — the standard a candidate must meet before it counts as a test rather than a story.

**This is a pointer, not a second copy.** The four conditions are stated once, authoritatively, in [`discriminators.md`](../../03-solutions-baseline/3.3-prediction/discriminators.md), alongside the candidates they govern. Restating them here would create two versions that can drift, and the one that drifts is always the copy.

A Tier 3 discriminator must:

1. **Forbid** an observation.
2. Forbid something the **rival account does not equally forbid** (ordinary historical geology).
3. Be **evaluable against a defined sample**.
4. State its **failure condition before evaluation**.

Read the authoritative statement, the registered candidates, and the checked-and-rejected entries in the file above.

**Tier discipline (see [`methods.md`](../../04-construct/methods.md) rule 10):** these four conditions govern **Tier 3 only**. Retrodiction and re-description are expected Tier 2 work, tagged `forbids: none`; holding interpretive work to the Tier 3 bar is a tier error, and has been made once already.

**Standing state:** nine candidates registered, two checked and rejected (retained, not deleted), and **zero evaluated against data**. The programme's verdict is *unappraised* for exactly this reason.

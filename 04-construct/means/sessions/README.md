# Session journal

One dated entry per working session — the programme's development history and its Lakatosian problemshift record. Entries travel with the repo (durable, versioned), which is the point: a session's reasoning should survive the conversation that produced it.

**Bracket each session** with the lifecycle scripts:

- start: `python3 04-construct/means/ops/research-start.py` (orientation briefing, read-only)
- wrap: `python3 04-construct/means/ops/research-wrap.py` (hygiene gate) — then add the entry below

**Convention:** `YYYY-MM-DD[-tag].md`. Capture: what was worked, what confirmed, what was **recorded as a refutation** (a refutation is a completed result here, not a cost), which packages or claims changed, and a **Carry to next** section, which `research-start.py` surfaces at the next session's open.

**Relationship to [`dev-notes/`](../../../dev-notes/).** They are different records and both are kept. A dev-note tracks *one question* across however many sessions it takes to resolve, and graduates into the belt when it does. A session entry tracks *one session* across however many questions it touched. A claim's history lives in the dev-note; the programme's working history lives here.
